# «Сборка» — демо-магазин комплектующих ПК

Демо-проект для портфолио: интернет-магазин, у которого сайт, Telegram-бот и админка работают на одном бэкенде.
Покупатель может оформить и оплатить заказ на сайте или прямо в Telegram. Владелец видит все заказы в админке
и получает уведомления в Telegram.

**Стек:** Java 21, Spring Boot 4, PostgreSQL 16, Flyway, Thymeleaf, Spring Security, TelegramBots, Testcontainers.

## Что умеет

**Сайт**
- каталог из 8 категорий и фильтры по характеристикам (сокет, тип памяти, объём, мощность и т. д.), сортировка, страницы;
- поиск в шапке по названию и бренду: «rtx 5070 asus» находит товар, где есть все слова;
- карточка товара с фото, характеристиками и остатком;
- корзина, оформление заказа, тестовая оплата, страница статуса заказа.

**Конфигуратор «Собрать ПК»** (`/configurator`)
- выбор процессора, платы, кулера, памяти, видеокарты, накопителя, блока питания и корпуса в любом порядке;
- проверка совместимости: сокет, тип памяти, форм-фактор платы и корпуса, длина видеокарты, высота кулера и размер радиатора СЖО, мощность блока питания с запасом, встроенная графика и кулер в комплекте у процессора, SSD с PCIe 5.0 на плате без него;
- в списке выбора сначала подходящие детали, у неподходящих написано почему;
- итоговая цена, примерное потребление и рекомендуемая мощность блока питания;
- четыре готовые сборки для старта, вся сборка в корзину одной кнопкой;
- сборка целиком хранится в ссылке, поэтому ею можно поделиться;
- сохранение сборок в личном кабинете.

**Аккаунт покупателя**
- регистрация и вход по email и паролю, пароли хранятся в виде bcrypt-хеша;
- личный кабинет: история заказов, профиль, смена пароля;
- адреса доставки: несколько адресов, основной адрес, изменение и удаление;
- при оформлении подставляются имя, телефон и сохранённые адреса. Новый адрес можно сохранить одной галочкой, а телефон из первого заказа запоминается;
- оформить заказ можно и без регистрации.

**Telegram-бот**
- каталог по категориям и карточки товаров;
- корзина, оформление (имя → телефон кнопкой «Отправить контакт» → адрес);
- оплата через Telegram Payments, а без платёжного токена работает тестовая кнопка;
- «Мои заказы» и уведомления покупателю, когда меняется статус;
- «🛠 Собрать ПК»: тот же конфигуратор в чате. Бот показывает только совместимые детали, есть готовые сборки и кнопка «Всё в корзину».

**Админка** (`/admin`, вход по логину и паролю)
- заказы с фильтром по статусу и смена статуса (при отмене товар возвращается на склад);
- товары: цена, остаток, снять с продажи, загрузить или убрать фото (JPEG, PNG, WebP до 3 МБ; тип проверяется по содержимому файла).

**Под капотом**
- Характеристики товаров хранятся в JSONB. Фильтры и количество товаров по каждому значению (фасеты) считаются SQL-запросом, поэтому новая категория не требует новых таблиц.
- Остаток резервируется атомарно (`update … where stock >= :qty`): два покупателя не купят последнюю видеокарту дважды.
- Админка и сайт — две отдельные зоны Spring Security: владелец входит по HTTP Basic, покупатели по форме входа. CSRF-защита включена везде, в том числе для JSON-API оформления заказа.
- Правила совместимости проверяют любую частичную сборку. Чтобы понять, почему деталь не подходит, конфигуратор подставляет её в сборку и смотрит ошибки, которые касаются её слота: отдельных правил «для списка» нет.
- Сохранённый адрес при заказе берётся из базы по id и только среди адресов этого аккаунта, текст адреса от браузера не используется.
- Уведомления отправляются после коммита транзакции и асинхронно, так что заказ не зависит от доступности Telegram.
- Интеграционные тесты идут на настоящем PostgreSQL в Testcontainers. Покрыты каталог, заказы, склад, страницы сайта, админка, правила совместимости, конфигуратор на сайте и в боте и полный сценарий покупки в боте.

## Быстрый старт (Docker)

Нужен Docker с Compose.

```bash
cp .env.example .env      # при желании впишите токен бота, см. ниже
docker compose up -d --build
```

- Сайт: http://localhost:8080
- Админка: http://localhost:8080/admin (логин и пароль из `.env`, по умолчанию `admin` / `change-me`)

Бот запускается, только если в `.env` указан `BOT_TOKEN`. Без него сайт и админка работают как обычно.

## Запуск для разработки

Нужны JDK 21 и PostgreSQL.

```bash
# база (или своя локальная: БД pcshop, пользователь pcshop / pcshop)
docker run -d --name pcshop-db -p 5432:5432 \
  -e POSTGRES_DB=pcshop -e POSTGRES_USER=pcshop -e POSTGRES_PASSWORD=pcshop postgres:16-alpine

./gradlew bootRun
```

Схему и каталог (около 130 актуальных товаров с ценами на октябрь 2026) создаёт Flyway при первом запуске (`src/main/resources/db/migration`).

Переменные окружения те же, что в `.env.example`. Для `bootRun` их можно экспортировать в shell или прописать
в конфигурации запуска IDE.

Тесты (нужен запущенный Docker):

```bash
./gradlew test
```

## Переменные окружения

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `DB_URL`, `DB_USER`, `DB_PASSWORD` | подключение к PostgreSQL | `localhost:5432/pcshop`, `pcshop` / `pcshop` |
| `DB_SCHEMA` | своя схема, если база общая с другим проектом | `public` |
| `PORT` | порт сайта | `8080` |
| `SHOP_BASE_URL` | публичный адрес сайта для ссылок из бота | `http://localhost:8080` |
| `ADMIN_USER`, `ADMIN_PASSWORD` | вход в админку | `admin` / `admin` |
| `BOT_TOKEN` | токен бота от BotFather; пусто = бот выключен | — |
| `BOT_USERNAME` | имя бота без `@`, для ссылки на сайте | — |
| `ADMIN_CHAT_ID` | куда слать уведомления о заказах | — |
| `TELEGRAM_PAYMENT_TOKEN` | платёжный токен; пусто = тестовая кнопка оплаты | — |

Токены не хранятся в коде, только в `.env`, а `.env` указан в `.gitignore`.

## Настройка Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте название и имя.
   Токен вида `123456:ABC…` впишите в `BOT_TOKEN`, имя бота в `BOT_USERNAME`.
2. Узнайте свой chat id: напишите [@userinfobot](https://t.me/userinfobot), он ответит числом. Впишите его в `ADMIN_CHAT_ID`.
   Перед этим нажмите «Start» в своём боте, иначе он не сможет вам писать.
3. Перезапустите приложение и отправьте боту `/start`.

Бот работает через long polling, поэтому вебхук, домен и HTTPS для него не нужны.

### Оплата в Telegram

Без платёжного токена бот показывает кнопку «Оплатить … (тест)», и заказ сразу помечается оплаченным.

Чтобы подключить настоящую форму оплаты Telegram:

1. В @BotFather: `/mybots` → ваш бот → **Payments**.
2. Выберите провайдера (например, ЮKassa) и тестовый режим. BotFather выдаст токен вида `381764678:TEST:…`.
3. Впишите его в `TELEGRAM_PAYMENT_TOKEN` и перезапустите.

В тестовом режиме платёж проводится тестовой картой провайдера, деньги не списываются. Для приёма реальных платежей
нужен договор с провайдером и боевой токен (`…:LIVE:…`).

## Деплой на Render (бесплатно, для демо)

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/grebecq/pc-shop/tree/stage-1-shop)

В репозитории лежит `render.yaml`: Render сам поднимет приложение из Dockerfile и бесплатный PostgreSQL.

1. Зарегистрируйтесь на [render.com](https://render.com) через GitHub.
2. Нажмите кнопку выше (или Dashboard → New → Blueprint → репозиторий `pc-shop`) и подтвердите **Apply**.
3. Дождитесь окончания сборки. Адрес сайта будет на странице сервиса `pc-shop`, вида `https://pc-shop-xxxx.onrender.com`.
4. Пароль админки: сервис `pc-shop` → Environment → `ADMIN_PASSWORD`, логин `admin`.

Ограничения бесплатного тарифа: после 15 минут без запросов сервис засыпает, и первый заход потом занимает около минуты. Бесплатная база на Render живёт 30 дней, и в аккаунте может быть только одна. Если она уже занята другим проектом, создайте сервис без базы и укажите в его переменных данные существующей базы и `DB_SCHEMA=pcshop`: таблицы магазина лягут в отдельную схему.

## Деплой на VPS

1. Установите Docker на сервер и скопируйте проект (`git clone`).
2. Создайте `.env` из `.env.example`. Обязательно смените `ADMIN_PASSWORD` и `DB_PASSWORD`, а в `SHOP_BASE_URL` укажите свой домен.
3. `docker compose up -d --build`.
4. Для HTTPS поставьте перед приложением обратный прокси, проще всего [Caddy](https://caddyserver.com/):

   ```
   shop.example.ru {
       reverse_proxy localhost:8080
   }
   ```

   Caddy сам получит сертификат. Приложение понимает заголовки `X-Forwarded-*`, поэтому ссылки и редиректы будут с https.

Данные базы хранятся в Docker-томе `db-data` и переживают перезапуск и пересборку.

## Структура

```
src/main/java/dev/pcshop/
  catalog/   товары, категории, поиск с фильтрами по JSONB, REST /api/products
  build/     конфигуратор: сборка, правила совместимости, готовые и сохранённые сборки
  order/     заказы, резерв склада, статусы, события, REST /api/orders
  bot/       Telegram-бот: каталог, корзина, оформление, оплата
  notify/    уведомления владельцу и покупателю
  web/       страницы сайта и тестовая оплата
  admin/     админка
  config/    настройки, безопасность, форматирование цен
src/main/resources/
  db/migration/  схема и каталог (Flyway)
  templates/     страницы (Thymeleaf)
  static/        CSS и JS корзины
```
